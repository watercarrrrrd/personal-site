# AI 开发规范文档（AGENTS）

> 项目名称：个人展示网站（Personal Portfolio Site）
> 文档版本：v1.0
> 编写日期：2026-10-19
> 适用范围：本项目全部 AI 辅助开发工作

---

## 1. 项目概述

本项目是一个**纯静态个人展示网站**，采用深色主题 + 星空动效，完整呈现个人介绍、技能、项目与博客内容，并实现全终端响应式适配。

- **技术栈**：原生 HTML5 + CSS3 + 原生 JavaScript（ES6+），Canvas 2D 星空粒子。
- **核心约束**：零框架、零外部依赖、零外部 CDN、内联 SVG 图标、单文件结构。
- **交付形态**：可直接部署的静态文件（`index.html` + `css/style.css` + `js/main.js`）。

所有 AI 生成代码必须严格遵循本规范，并与 `PRD.md`、`TECH_DESIGN.md` 保持一致。

## 2. 代码开发规范

### 2.1 命名规范

#### HTML

- 使用语义化标签：`<header>`、`<nav>`、`<section>`、`<article>`、`<footer>`。
- 类名使用小写字母 + 连字符（kebab-case），如 `skill-bar`、`project-card`。
- `id` 仅用于锚点定位（如 `#about`、`#skills`），保证唯一。

#### CSS

- 类名遵循 **BEM 命名**：`block__element--modifier`，如 `nav__item--active`、`project-card__title`。
- CSS 变量统一前缀，如 `--bg-primary`、`--accent`，集中定义在 `:root` 中。
- 动画关键帧使用描述性命名，如 `@keyframes fade-in`、`@keyframes twinkle`。

#### JavaScript

- 变量与函数使用 camelCase，如 `initStarfield`、`particleCount`。
- 类名使用 PascalCase，如 `Particle`、`Starfield`。
- 常量使用 UPPER_SNAKE_CASE，如 `MAX_PARTICLES`、`BREAKPOINTS`。
- 避免使用无意义缩写，保持可读性。

#### 文件

- 文件统一小写命名：`index.html`、`style.css`、`main.js`。
- 目录统一小写：`css/`、`js/`、`docs/`。
- 文档文件使用大写扩展名约定的命名：`PRD.md`、`TECH_DESIGN.md`、`AGENTS.md`。

### 2.2 代码风格

| 项目 | 规范 |
| --- | --- |
| 缩进 | 统一使用 2 个空格，禁止 Tab |
| 注释 | 关键逻辑、复杂函数、模块开头必须添加注释；注释说明「为什么」而非「做了什么」 |
| 引号 | 统一使用双引号（HTML 属性、JS 字符串） |
| 分号 | JS 语句末尾统一加分号 |
| 空行 | 逻辑块之间保留一个空行，增强可读性 |
| 行宽 | 单行代码尽量不超过 100 字符 |

### 2.3 结构规范

#### HTML

- 页面采用单文件结构，按 `导航 → Hero → 关于我 → 技能 → 项目 → 博客 → 页脚` 顺序组织。
- 每个区块使用 `<section>` 包裹，并配置对应锚点 `id`。
- 交互元素（链接、按钮）使用语义化标签，不滥用 `<div>`。

#### CSS

- 按以下顺序分层组织：
  1. CSS 变量（`:root`）
  2. 基础重置（reset）
  3. 全局布局（布局容器）
  4. 组件样式（导航、卡片、进度条等）
  5. 动画关键帧
  6. 响应式媒体查询
- 避免使用 `!important`，通过选择器优先级与结构控制样式。

#### JavaScript

- 按功能模块拆分逻辑：星空背景、导航交互、滚动动画各为独立函数。
- 使用 `DOMContentLoaded` 事件统一初始化，避免脚本阻塞渲染。
- 将 `<script>` 标签置于 `<body>` 末尾，或使用 `defer` 加载。

### 2.4 资源规范

- **零外部 CDN**：不引入任何外部脚本、样式库、字体、图片。
- **内联 SVG**：所有图标以内联 SVG 形式直接写在 HTML 中，不发外部请求。
- **单文件**：仅保留一个 HTML 文件、一个 CSS 文件、一个 JS 文件，不拆分模块文件。
- **无外部图片**：不使用外部图片资源，视觉元素全部通过 CSS 或 Canvas 实现。

## 3. 测试与验收要求

### 3.1 功能测试

- 七个功能模块（导航、Hero、关于我、技能、项目、博客、页脚）全部可见且内容完整。
- 导航菜单点击后能平滑滚动并正确定位到对应区块（不被吸顶导航遮挡）。
- 滚动到不同区块时，导航项高亮状态正确切换。
- 技能进度条在进入视口时触发填充动画。

### 3.2 兼容性测试

- 在 Chrome、Edge、Firefox、Safari 最新两个大版本上验证页面正常显示、无控制台报错。
- 在 375px（手机）、768px（平板）、1440px（桌面）三种宽度下验证无横向滚动条、布局正常。

### 3.3 性能测试

- 首屏渲染完成时间 < 2 秒（4G 网络下）。
- 星空动画平均帧率 ≥ 60fps。
- 页面总体积 ≤ 100KB，HTTP 请求数 ≤ 3。

> 详细验收标准以 `PRD.md` 第 9 章「MVP 验收标准」为准。

---

## 4. 注意事项

1. **功能优先**：先保证核心功能可用，再追求动效与视觉细节，避免因过度设计影响交付。
2. **严格 MVP**：只实现 PRD 中标注为 Must have / Should have 的功能，不擅自扩展 Won't have 的功能范围。
3. **遵循设计**：严格遵循 PRD 第 4 章的视觉规范（配色、圆角、字体、间距），不偏离既定设计。
4. **可直接运行**：生成的代码必须开箱即用，无需任何构建步骤，双击 `index.html` 即可在浏览器中打开。
5. **无障碍**：为图标提供替代文本，保证语义化结构与足够的对比度，兼顾键盘操作。
